# Codex analytics status

The `/api/codex-analysis` route calls the `gpt-5.3-codex` model via the Responses API. This is a Codex-tuned model, not a Codex agent session. OpenAI marks the model deprecated; live synthetic tests succeeded for each modality on 1 November 2026. The request uses only validated numeric readings, no tools, a strict action schema, `store: false`, low reasoning effort, and a maximum of 768 output tokens. The model selects a recording tip; fixed text and the received readings form the report. Provider errors return 503 and are not retried. Configure `OPENAI_API_KEY` and the separate `CODEX_ACCESS_TOKEN` as Worker secrets; the Pages service must send the matching bearer token and obtain the participant's agreement before calling.

Both analytics routes use the same durable counter and `resona-sensor-demo` object as the earlier demo. The lifetime cap is 24 reservations, including earlier attempts. A reservation is consumed before a provider call, including failed calls. The request body is limited to 1,024 bytes. At the [published model prices](https://developers.openai.com/api/docs/models/gpt-5.3-codex), assuming a conservative 8,192 input tokens and the full output limit for every reservation, 24 Codex requests would cost at most about $0.61; earlier model-comparison spend must also be counted against the user's $1 authorization. Pricing and model availability can change, so recheck before modifying the model or cap.

An earlier synthetic request on 1 November 2026 to `POST /v1/agents/sessions` received HTTP 400 with `unknown_parameter` for `spend_control`. The [Python SDK reference](https://developers.openai.com/api/reference/python/resources/beta/subresources/agents/subresources/sessions/methods/create) lists a top-level session limit in US cents, while the [REST create reference](https://developers.openai.com/api/reference/resources/beta/subresources/agents/subresources/sessions/methods/create) does not list this field. No session ID or usage was returned. The Responses request above has a bounded output and uses the shared counter; it is not an agent session and must not be described as one.

The REST reference requires an input when using an environment of type `none` and permits an input array with zero items. Whether `input: []` creates an idle session has not been verified. Before submitting any readings, a future implementation must confirm the session is idle, durably register its ID and schedule cleanup. Keep the existing `resona-sensor-demo` Durable Object and its counter; a new Worker namespace would reset the effective cap. Do not log requests, outputs, credentials, or readings.

Agent session content is retained until deletion, with physical cleanup asynchronous. The [data controls](https://developers.openai.com/api/docs/guides/your-data) describe the retention of abuse-monitoring logs and the service's residency. Tell participants what will be sent and obtain their agreement before a provider call. Durable cancellation and deletion retry after disconnect remain unimplemented for agent sessions; do not enable an agent-session integration until tested.
